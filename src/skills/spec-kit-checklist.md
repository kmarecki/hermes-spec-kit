# spec-kit-checklist

**Phase**: Any (Auxiliary)

**Purpose**: Generate or update targeted checklists at `specs/[feature]/checklists/[name].md` for validating specific aspects of the SDD workflow.

**Prerequisites**: None required, but `spec-kit-specify` needed for feature-specific checklists

**Artifacts**:
- `specs/[feature]/checklists/[name].md`

## Execution

### Step 1: Determine checklist type
User specifies the domain/context. Common types:

**requirements.md** (generated by spec-kit-specify):
- Content Quality: no implementation details
- Requirement Completeness: testable, measurable
- Feature Readiness: acceptance criteria mapped

**constitution.md**:
- Article I (Library-First): feature as standalone library
- Article II (CLI Mandate): text-in/text-out interfaces
- Article III (Test-First): tests before implementation
- Article VII (Simplicity): ≤3 projects
- Article VIII (Anti-Abstraction): framework used directly
- Article IX (Integration-First): real environments over mocks

**architecture.md**:
- Project structure decisions
- Technology choices justified
- Complexity justifications documented

**test.md**:
- Contract tests defined
- Integration tests planned
- E2E tests scoped
- Unit test coverage targets

**security.md**:
- Authentication/authorization verified
- Data protection documented
- Security assumptions checked

**implementation.md**:
- TDD workflow followed
- Phase order respected
- Checkpoints validated

### Step 2: Generate checklist
Use format:
```
# [Type] Checklist: [Name]

**Purpose**: [validation scope]
**Created**: [DATE]
**Feature**: [link]

## [Category 1]
- [ ] CHK001 [Action with specific criteria]
- [x] CHK002 [Completed item]

## [Category 2]
- [ ] CHK003 [Action with specific criteria]

## Notes
- Items marked incomplete require updates before proceeding
- Check items off as completed: [x]
```

### Step 3: Number items
Format: CHK### prefix (CHK001, CHK002, etc.)
Group by category
One action per item

### Step 4: Provide validation guidance
Add brief notes explaining:
- How to verify each item
- What to look for
- Common failure modes

### Step 5: Complete

Report:
- Checklist path
- Item count by category
- Completion status
- Suggest what to do with results
